# AIC GE A8 遮罩混合（2026-10-26）

本次补齐 `blend_a8_rgb565`，让字形/透明四边形可通过 GE 混合。原 fill 和 PSM5650 搬运保留。
未改 CPU 主频、feature profile、堆或 JS 配额；缩放/旋转继续保留软件采样路径。

## 实现

GE 没有 A8 格式，CPU 将遮罩与全局 alpha 按 `(mask * alpha + 127) / 255` 合并，
写入 straight ARGB8888。源色不预乘，使用 `alpha_en=1` / `GE_PD_NONE`、像素源 alpha
与不透明目标。SDK `aic_drv_ge.h` 的 alpha_en 注释倒置，以 `hal_ge_normal.c` 的实际
分支与系数设置为准。

首次有效请求从统一系统堆申请 49215 B：8192 个 ARGB8888 源像素、8192 个 RGB565 目标
像素和 63 B 对齐余量，后续复用，关闭宿主释放。源/输出各自 64 B 对齐。
8192 像素内的局部矩形先复制背景到私有输出面，clean 源与输出、同步 bitblt、invalidate
输出后才逐行写回。GE 失败也 invalidate 私有输出，但不写回，因此软件回退不会重复混合。
无效区域、短遮罩、超限区域或暂存分配失败返回软件路径；分配失败后不反复申请。
异步 cmdq 模式不注册加速表，避免提交后读取未完成的输出。

## 用户黑屏反馈与 SDK 示例核对

用户回传日志已到 S4-mount、GE normal ready 与 S5-gc，S5-gc 系统占用 4221404 B，
历史系统峰值 5343736 B，caps_fails=0；随后没有 S5-frame1。说明应用挂载和首帧前 GC
已结束，但日志不足以确认卡在 JS tick、fill 还是 A8 DMA，不能把“无分配失败”写成排除所有内存问题。
原始回传保存在忽略目录 `dist/aic/ge-a8-recovery-cpu/user-blackscreen.log`。

上一轮查看了驱动，但没有逐项核对示例的图像内存布局，测试还把 packed 奇数宽行当作合法。
本次核对：

- `packages/artinchip/mpp/mpp_test/ge_test/public/ge_mem.c`：ARGB8888/RGB565 stride
  都通过 `BYTE_ALIGN(..., 8)` 对齐，图像数据使用 `aicos_malloc(MEM_CMA, ...)`。
- `packages/artinchip/mpp/mpp_test/ge_test/example/alpha_blend_example.c`：
  清理缓存后 `mpp_ge_bitblt → mpp_ge_emit → mpp_ge_sync`，`alpha_en=1`。
- 当前 normal_ops 的 emit/sync 均返回 0，不承担等待；实际等待仍在 ioctl 中。
  因而补上这两个调用是对齐接口，不能宣称这就是卡死原因。

初版只对齐首地址，stride 仍是 `rect.width * 4/2`。例如宽 27 时为 108/54 B，
均不满足 SDK 示例的行对齐约束。修正版共用四像素对齐 pitch，宽 27 时 pitch=28、
stride=112/56 B，转换、DMA 缓存范围和写回都使用 padded pitch，输出宽度保持 27。
padding 计入 8192 像素容量，超限保留 CPU，避免越界。

暂存申请改用 MEM_CMA，并由同一 allocator 释放。它占用 CMA 运行余量，不再计入 SW
系统堆；修正版静态 CMA 扣双 framebuffer 余量为 243764 B，首次申请约 48 KiB 另扣。
不改变分区、CMA/SW 边界或 guest 配额。fill/PSM5650 路径也拒绝非 8 B 对齐行 stride。

新增首次 fill begin/end、首次 A8 begin/submit/end 日志，记录矩形、pitch、地址、stride
和返回值，用于后续定位实际停点。mock 新增强制 stride%8 检查、MEM_CMA allocator 检查、
带 padding 的逐像素结果、emit/sync 失败不写回；地址/UB 检查通过。
这些是已确认的实现缺口和本地修正，**这些调整未做逐项 A/B，无法单独归因；修正版出帧后续已获用户确认（见下节）**。
