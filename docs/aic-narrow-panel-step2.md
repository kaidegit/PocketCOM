# AIC 内存优化第 2 步：连接配置延后创建

日期：2026-10-23。状态：本地对照、桌面交互、固件构建通过，等待用户烧录及真机日志。第 1 步的真机启动与基本交互结果继续保留，不能把本步离板结果写成板端通过。

## 最终改动与边界

同一套共享 App 在视口宽度小于 720px 时，默认不创建连接配置面板，顶部用 32px 操作栏打开配置抽屉，工作区使用全宽。抽屉复用 `LeftPanel`，宽 272px，通过 Portal 和显式视口尺寸遮罩显示；返回、点遮罩或 Escape 收起。提供上翻/下翻按钮访问短屏中的配置项。宽屏布局保持原来的左右分栏。

**首次打开才创建，关闭后移出视口，后续复用同一个实例。** 面板首次创建后的内存不会因关闭而全部退回启动基线。本步主要收益是首次打开配置前的启动工作集，不能声称所有运行状态都减少 30.7%。切回宽屏时卸载窄屏实例，释放滚轮订阅和字段句柄。

起初验证过关闭即卸载：有显式 GC 的 200 次开关能完成，但历史峰值为 7,013,211 bytes；快速开关、不额外触发 GC、限制 caps 为 7 MiB 时失败。因此交付版本采用首次创建后复用，以避免重建峰值；失败方案的原始证据仍保留，不作为交付结果。生产 GC 策略没有改变，也没有从 App 主动调用 GC。

工作区、发送草稿、会话和日志/终端模型不随抽屉开关卸载。关闭配置时提交未按 Enter 的字段文字并清除活跃输入域；打开应用配置先收起连接抽屉。布局几何同时用于收发区、终端、选区及滚轮路由；发送输入宽度改为由可用工作区显式计算。隐藏配置字段不参与工作区选区命中。

本步先更新 SPEC §3.1，再实现；不调整 JSON profile、容量、字体选择、堆/栈、设备桥或 allocator。高级收发工具栏在 480px 下仍有溢出，后续另做折叠；当前 AIC 无 `com.*` 桥，实际显示共享空态。本步不代表完整窄屏产品 UI、板端收发或软键盘已验收。

## 启动空闲 A/B

前后各三个独立进程、每次 120 turns，5 MiB JS 配额，不注入 caps 预算，不主动收集 GC，无触摸。每组下列读数三次一致。两组均无设备桥、业务收发或终端网格；优化前配置面板常驻，优化后尚未首次打开。

单位 bytes；caps、js、guest 相互包含，不可相加：

| 指标 | 第 1 步 | 本步 | 减少 |
|---|---:|---:|---:|
| 全程 caps 历史峰值 | 6,023,152 | 4,753,774 | 1,269,378（21.07%） |
| S4 挂载 caps 存活 | 5,136,291 | 3,629,787 | 1,506,504（29.33%） |
| S5 空闲 caps 存活 | 5,279,682 | 3,658,105 | 1,621,577（30.71%） |
| S5 caps 块数 | 33,987 | 20,793 | 13,194（38.82%） |
| S5 JS malloc_size | 2,903,141 | 2,059,627 | 843,514（29.05%） |
| S5 JS 对象数 | 7,223 | 3,134 | 4,089（56.61%） |
| 正常帧 / 错误帧 | 120 / 0 | 120 / 0 | — |
| caps 分配失败 | 0 | 0 | — |

即启动峰值 5.74 → 4.53 MiB，首次打开前空闲存活 5.04 → 3.49 MiB。新文案使 UI 烘焙字形从 233 增至 237，PAK 从 522,160 增至 530,032 bytes（+7,872）；两种字体保持不变，资源增长已包含在上述结果。

## 操作峰值与记录环回卷

探针新增可重复的 `--tap X,Y@TURN`、`--sample TURN` 和实验用 `--collect TURN`。触摸为该帧按下、下一帧释放；S6 为附加采样，S7 为显式 guest GC 后采样。每类最多 512 条。交付 App/固件没有这些实验 GC 指令。

| 交付包场景 | caps 存活 | 历史峰值 | 正常帧 / 错误帧 | 分配失败 |
|---|---:|---:|---:|---:|
| 第一次打开后关闭，turn 120 显式 GC | 5,324,924 | 5,598,206 | 120 / 0 | 0 |
| 200 次快速开关，不额外 GC | 5,424,624 | 5,598,206 | 4,000 / 0 | 0 |
| 200 次开关、48,000 turns，周期采样/GC | 5,936,508 | 5,940,556 | 48,000 / 0 | 0 |

后两组 caps 预算为 7 MiB。快速组每 20 turns 一轮，按下为 `5+20i` 和 `12+20i`；长测每 240 turns 一轮，按下为 `5+240i` 和 `65+240i`，在 `120+240i`、`240+240i` 显式收集 GC。打开点 `(60,16)`，返回点 `(238,22)`。完整参数分别保留为 `after/rapid-final-command.json`、`after/interaction-final-command.json`；不是实际等待 800 秒的硬件压力测试。

长测在 turn 35,880、43,080、47,880 的 GC 后读数均为：caps 5,936,508 bytes、38,418 块、JS 对象 9,026 个，尾部不再线性增长。历史峰值约 5.67 MiB，关闭后约 5.66 MiB；这组状态和无触摸启动空闲不可混作一个稳态数字。

前期小幅增长并非由面板节点泄漏直接推出：原生节点及帧回调计数随卸载回到固定数量，空白区域触摸也产生同量增长。PocketJS `devtools.ts` 默认记录最近 36,000 帧输入，触摸页按需分配（每页 128 帧），回卷后覆盖旧页。此次长测确实跨过回卷并观察到平台；不把记录缓存增长误写成无限泄漏，也不由此保证所有其他交互均有界。

探针是 64 位 malloc 环境，不含 RT-Thread 线程/WiFi、TLSF 碎片或真实绘制成本；周期显式 GC 用来观察存活集，不模拟板端空闲 GC 时序。快速组无需额外 GC 通过，是选择复用方案的重要依据。`caps_peak ≤4 MiB` 候选目标仍未达到。
