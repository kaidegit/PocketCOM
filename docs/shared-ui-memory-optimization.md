# PocketCOM 共享 UI 与编译期裁剪方案

日期：2026-10-12。状态：设计提案，尚未实施。适用范围：PocketCOM 的 TypeScript 应用、PocketJS Vue Vapor 适配层及 AIC / macOS 构建链。

**后续主线采用同一套 `app/`、`core/` 和基础控件，通过编译期功能裁剪、共享实现的内存优化、按需挂载和容量配置适配 AIC。** macOS 保留完整功能，AIC 选择可承受的功能组合。现有 `app/aic.tsx` 保留作启动诊断基线，后续产品界面从现有组件演进，不再以它扩写一套独立 UI。

本文调整[原内存方案](aic-memory-optimization.md)中方案 A 的实现方向；原文的实测数据、全链路限额要求及字节码 / realloc 研究仍有效。本次只记录方案并更新文档入口，未切换板端入口、修改运行时代码或重新测量。正式实现前需按第 10 节更新 [SPEC](../SPEC.md) 中对应的后续路线与平台差异。

## 1. 共享的边界

共享代码可以生成不同的构建产物，也可以根据视口挂载不同数量的控件。建议按下表划分：

| 层次 | 共享内容 | 允许的差异 |
|---|---|---|
| `core/` | 会话、消息总线、编解码、日志、终端等纯 TS 实现 | 构造参数、容量上限、启用的模块 |
| `app/` | `App`、连接配置、收发区、设置、基础控件和输入行为 | 编译期功能分支、视口布局、已挂载的功能区 |
| 启动装配 | 同一个应用模型工厂和启动流程 | 宿主服务、初始视口、构建 profile |
| PocketJS | Vue Vapor 适配器、节点模型、编译器 | 通用功能裁剪与宿主能力配置 |
| `host/*` | 同一个 `com.*` 语义契约 | macOS 原生 IO 与 RT-Thread 驱动实现 |

最终允许 `main.tsx` / `main.aic.tsx` 两个很薄的启动文件，但两者都装配同一应用、挂载同一个 `App`。不新增 `AicPanel`、`AicReceivePane`、板端专用会话逻辑等平行实现。宿主适配和构建配置仍各自存在。

优化按成本来源分开验收：

1. **代码成本**：被禁用的模块、函数字节码、字符串、资源是否仍进入产物。
2. **实例成本**：是否仍创建模型、响应式状态、watcher、订阅和后台任务。
3. **节点成本**：当前界面挂载多少节点，每个节点的 JS / 原生开销是多少。
4. **数据成本**：历史、缓冲、格式化副本和短时突发是否有上限。

运行时隐藏一个入口只解决其中一小部分；把四项分别做小，才可能覆盖启动和持续运行。

## 2. 当前证据支持什么

### 2.1 已记录的板端结果

以下引用[原方案 §2.1.3–2.1.4](aic-memory-optimization.md)，并非本次重新测得。单位统一用 bytes，避免混用十进制 MB 与 MiB。

| 观测 | 精简诊断页 | 完整 App 诊断构建 |
|---|---:|---:|
| S3 编译后历史 `sys_max` | 3,369,880 | 5,478,612 |
| S3 编译后历史 `caps_peak` | 2,930,837 | 5,029,764 |
| S4 挂载结果 | 成功 | 执行 / 挂载阶段失败 |
| S4 后历史 `sys_max` | 3,369,880 | 6,876,604 |
| S4 后 QuickJS `malloc_size` | 1,159,547 | 2,946,998 |
| `heap_caps` 分配失败 | 0 | 6 次，记录的请求为 68 / 344 / 380 bytes |

当前统一系统堆为 7,340,032 bytes，JS 配额为 5 MiB。完整 App 的失败发生在底层分配，不能通过提高 JS 配额解决。异常退出后的空闲块快照也不能当作失败瞬间的可分配空间。

早前本机同版本 QuickJS probe 的完整 UI 分配峰值为 8,904,442 bytes，稳态约 8.1 MiB；它帮助确认工作集过大，但本机数据不能替代板端验收。WiFi 已编入、未开启时的基线也不能代表连 AP 并持续传输时的预算。

这些证据说明现有完整启动图需要缩减，并且需要减少细碎分配；**尚未证明共享组件经过优化仍然无法装入 AIC，也未证明哪一个组件独占了内存缺口。** 后续应测组件增量和单节点成本，而非从 OOM 直接推导出重新制作 UI。

### 2.2 源码中可直接定位的改造点

| 当前事实 | 对方案的影响 |
|---|---|
| [`app/session.ts`](../app/session.ts) 顶层创建总线、`Terminal`、`LogView`，注册订阅 / watch，并尝试加载配置 | 导入模块即装配应用；需要把可选功能初始化移入明确的工厂和生命周期 |
| `Terminal` 在收发模式也持续消费 RX，查询应答由每帧泵发回 | 只隐藏终端按钮无收益；但桌面端也不能直接改为首次打开终端才接收数据 |
| [`App`](../app/app.tsx) 已条件挂载收发 / 终端视图；[`SettingsModal`](../app/settings-modal.tsx) 的内容已按打开状态挂载 | 不应把“两个大视图和整个设置内容一直同时挂载”当成现状 |
| [`ReceivePane`](../app/transfer.tsx) 已只渲染可见行及前后各 3 行 | 保留虚拟列表；继续检查行包装对象、颜色 run 和节点复用，而非再造一套虚拟列表 |
| [`native-tree.ts`](../vendor/pocketjs/framework/src/native-tree.ts) 的 `decorateNativeNode()` 给每个节点新建访问器、捕获 `node` 的方法以及 `style` / `classList` 对象 | 有明确的 TS 对象与闭包优化入口，收益可同时覆盖两端 |
| [`theme.ts`](../app/theme.ts)、[`ansicolor.ts`](../core/ansicolor.ts)、[`logview.ts`](../core/logview.ts) 从 `core/term.ts` 导入颜色定义 | 禁用终端时仍有模块依赖；应拆出颜色叶子模块，并检查实际保留代码，不能假定整个终端必然已被裁掉 |
| [`locale.ts`](../app/locale.ts) 导入会话单例 | 通用语言工具可间接启动业务装配，需要解除这种依赖 |
| [`FrameCoalescer`](../core/framing.ts) 仅按静默间隔产帧，没有积累字节上限 | 总线限额不能阻止合流阶段先耗尽内存 |
| [`LogView`](../core/logview.ts) 有字符宽度 `Map`、整帧格式化和颜色 `subarray` | 长行、未知字符和短切片保活大缓冲必须专项测试 |

还有一个基线边界：AIC 当前没有 `com.*`，按现有 `App` 的 `comAvailable` 分支，右侧走“桥不可用”空态。完整 App 诊断构建包含完整依赖和模型装配，但不意味着所有收发控件都已挂载；实际设备桥接入后的界面增量需要另测。

## 3. 功能标记、宿主能力和内存配置分开

这三类信息解决不同问题，不能都塞进一个运行时 `isAic` 判断。

| 信息 | 决定什么 | 建议形式 |
|---|---|---|
| 产品构建功能 | 终端、MCP、配置文件等代码是否存在 | 编译期布尔常量，如 `__PC_TERMINAL__` |
| 宿主能力 | 当前宿主是否提供触摸、剪贴板、串口等接口 | 框架 capability + `com.*` 能力探测；仍处理运行失败 |
| 内存配置 | 历史、队列和单次操作的上限 | 类型化 `MemoryLimits`，显式传入模型 |
| 窗口几何 | 侧栏常驻还是折叠、工具栏如何布置 | 共享布局函数，根据 `viewportSize` 计算 |

建议产品维护 `desktop`、`aic-transfer` 两个受支持 profile；需要终端时再增加明确的实验组合。功能开关集中声明、校验，不让任意环境变量任意组合成无法回归的产品。

### 3.1 首轮功能组合建议

下表是后续实现的建议值，**不代表 AIC 当前已经具备这些功能**。AIC 目前仍无 `com.*` 设备桥。

| 功能 | macOS | AIC 首轮共享 UI |
|---|---|---|
| 收发、文本 / HEX、暂停、清屏、基本格式选项 | 保留 | 保留同一实现，使用较小容量 |
| 终端解析、终端视图、DSR / DA 应答 | 保留现有语义 | 编译关闭，后续单独测量再开放 |
| MCP 服务与 TS 中继、配置入口 | 保留 | 编译关闭整个功能路径 |
| 串口、TCP Client | 保留 | 先用回环验证 UI，实际桥接完成后逐项启用 |
| UDP、TCP Server、WebSocket | 保留 | 首轮关闭，按需求与桥接进度恢复 |
| 定时发送 | 保留 | 首轮关闭；手动发送共用 |
| 发送历史 | 保留 | 小容量，按条数与总字节数双限 |
| 基本设置、中文 / 英文、深浅主题 | 保留 | 复用原设置与语言包；首轮仍保留双语和主题 |
| 配置文件持久化、文件导入 / 导出 | 保留 | 首轮关闭；基本设置在 RAM 内生效 |
| 鼠标选区、右键、系统剪贴板 | 保留 | 按输入能力裁剪，触摸命中共用 |
| 字号选择 | 保留 12 / 14 / 16 | 先测资源成本，再决定是否固定一档 |

关闭 MCP 后，继续遵守当前日志语义：TX 行隐藏、RX 无方向前缀、系统消息走 i18n 和消息总线。关闭终端应同时消除模型、RX 订阅、应答泵、键盘路由、视图、选项和对应文案，不能只关闭一个按钮。

“功能编入”与“宿主已经提供”必须同时满足才可使用。连接类型列表、打开连接的动作入口、配置归一化都检查允许集合，避免导入旧配置后绕过 UI 限制；不支持的操作返回明确结果。

## 4. 编译期裁剪：从现有 PocketJS 编译器扩展

### 4.1 已有机制及其缺口

[`platform.ts`](../vendor/pocketjs/framework/src/platform.ts) 已提供 `hasFeature()`，`tools/build.ts` 已注入 `__POCKET_TARGET__` / `__POCKET_FEATURES__`。[`jsx-plugin.ts`](../vendor/pocketjs/framework/compiler/jsx-plugin.ts) 会把来自指定 import、参数为字面量的 `hasFeature()` 调用替换成布尔值，缓存键也已包含框架 feature 集合。

但这还不等于 PocketCOM 所需的完整裁剪：

- 当前 feature 集合来自已注册的宿主能力。`terminal`、`mcp` 是产品选择，不应伪装成 `input.touch` 一类框架能力。
- 现有替换器仅替换调用，本身不删除不可达分支。Vue Vapor 路径仍把原始 `src` 交给 `transformVueJsxVapor()`，随后再处理输出，可能先生成禁用 UI 的模板或辅助代码。
- pass 1 用原始源码中的 import 遍历模块并收集样式 / 字符；即便最终 JS 被 tree-shaking 删除，资源收集也可能已经发生。
- AIC 的 `compactBundle()` 只压缩标识符和空白，`syntax: false`，它不是产品功能裁剪器。

因此优先增加通用的“构建常量特化”步骤，不采用字符串替换 `#ifdef` 注释，也不只在最终 IIFE 上压缩。

### 4.2 建议的编译流程

```text
产品 profile + 宿主 build plan
  → 校验功能依赖、生成布尔常量与容量配置、计算配置指纹
  → TS / TSX AST 特化：替换标记、折叠条件、删除可证明不可达的分支
  → 处理已无引用的纯功能 import，形成特化后的模块图
  → Vue Vapor 转换 + 样式 / 文案 / 字形收集
  → Bun bundle / tree-shaking
  → AIC 压缩、PAK / .pocket 与构建报告
```

所有 pass 使用同一份特化结果和模块解析规则。普通 `.ts`、`.tsx`、框架能力标记都要覆盖；若扩展为通用编译器入口，还应明确 `.vue` 的支持范围，不能宣称未测试的格式已经支持。

关键约束：

1. **在 Vue 转换前特化。** 静态关闭的 JSX 不生成模板、effect 或资源引用。按 AST 和作用域识别声明过的标记，避免误替换字符串、同名局部变量或有副作用的表达式。
2. **保留合法副作用。** 静态 import 即使绑定未使用，模块仍可能有副作用。可选模块先做到“导入不分配、不注册”，再允许消除；有副作用的模块必须保留或报出裁剪失败。禁止对全仓库盲设 `sideEffects: false` 或补 `@__PURE__` 掩盖问题。
3. **两阶段模块图一致。** pass 1 不再扫描已剔除的功能依赖；只在 pass 2 删代码不能证明字体 / 样式已裁剪。
4. **缓存和构建身份包含产品配置。** 新的功能值、容量配置、语言子集和特化器版本纳入相应缓存、依赖记录和产物指纹；框架已有 `features` 哈希不自动覆盖新配置。若扩展 manifest / plan，同步 schema、resolver、hash 和验证测试。
5. **没有 profile 就失败。** 正式构建不允许未替换的产品标记进入 guest，也不静默按桌面全开回退。单测明确使用测试 profile；两端构建按目标隔离中间产物。

以下仅为拟议写法，标记、类型和模块名当前尚未实现；可选实例在共享装配工厂中创建：

```ts
declare const __PC_TERMINAL__: boolean;
declare const __PC_MCP__: boolean;

// 两个模块都必须无顶层装配副作用。
import { createTerminalFeature } from "./features/terminal";
import { createMcpFeature } from "./features/mcp";

function attachOptionalFeatures(base: BaseModel, limits: MemoryLimits) {
  const terminal = __PC_TERMINAL__
    ? createTerminalFeature(base, limits.terminal)
    : undefined;
  const mcp = __PC_MCP__ ? createMcpFeature(base) : undefined;
  return { terminal, mcp };
}
```

UI 与事件路由使用相同常量包围入口。不要把所有可选工厂先放进运行时注册表再挑选，注册表会保持引用。工厂延迟执行只能省实例内存；当前自包含 IIFE 仍整体编译，不能把工厂或普通动态 import 当成已支持的分段加载。

### 4.3 裁剪必须能被证明

建议输出一份构建裁剪报告：profile 指纹、参与模块、各模块输出贡献、JS / PAK 大小、字体槽 / 字形数、已禁用功能的检查结果。`tools/build.ts` 已开启 Bun metafile，可在此基础上保存报告。

验证至少覆盖：关闭终端 / MCP 后没有初始化、订阅和功能入口；禁用专属模块与资源确实消失；开启时功能完整；切换 profile 的热缓存不会串包；同配置冷 / 热构建可复现。字符串搜索只能辅助定位，混淆后的符号缺失不能单独证明裁剪成功。功能专属测试哨兵、模块报告和运行探针共同验收。

## 5. 共享 TS 实现如何降低实例与节点成本

### 5.1 将会话单例改成显式装配

逐步从 `app/session.ts` 提取一个共享的 `createAppModel(services, limits)`，保留当前组件调用方式的薄适配，避免一次改完全部 UI。基础模型只负责连接、总线、收发状态和日志；终端、MCP、持久化按功能模块装配。

- 先得到受 profile 约束的有效配置，再创建有容量要求的对象，避免先用桌面大配置创建、随后缩小。
- `start()` 注册必需的订阅 / watch；`dispose()` 释放订阅、定时发送、帧回调和页面持有的引用。组件卸载只释放视图资源，连接与消息总线继续存在。
- 语言模块保持独立，日志重排由装配层订阅语言变化；通用 helper 不再反向 import 整个会话单例。
- `core/` 继续接收普通参数，不 import Vue、平台 API 或产品构建标记。若类的方法粒度阻碍裁剪，先测保留代码，再按功能拆纯辅助函数；不要假定 tree-shaking 会删除所有未调用的类方法。
- 配置加载、UI 设置、配置导入及 MCP 修改（启用时）共用限额校验，任何入口都不能重新启用已裁剪功能。

桌面端终端持续接收 RX、保存屏幕和处理查询应答的语义继续保留。AIC 首轮通过“终端未编入”消除这笔成本；将来若要“进入终端才开始解析”，那是新的行为定义，必须先明确历史是否回放、查询应答时机和切换后的状态，不能当成无影响优化。

### 5.2 优先实验：节点访问器和方法共享

`decorateNativeNode()` 当前为每个节点执行 `Object.defineProperties()`，访问器闭包捕获该节点；随后创建一组同样捕获节点的方法，以及 `style` / `classList` 的小对象和函数。节点越多，这些函数对象、属性及包装分配越多。

建议在 `vendor/pocketjs` 做独立 A/B 改造：

- 把无差异方法和 getter / setter 放到共享原型，使用 `this` 访问节点；创建时选定原型，实例只保存 id、父子关系、文本、属性等数据。
- 审计 Vue 和适配器的调用方式，确认是否有方法脱离接收者调用、own-property 检查、属性枚举、clone 或 Proxy 依赖；不能机械把闭包改成 `this`，再给每个方法 `.bind(node)` 抵消收益。
- 不把可变的 `style`、`classList`、属性字典跨节点共享。先共享方法；容器是否惰性创建、无操作 facade 是否可共享，以调用契约和测试为依据。
- 对所有创建入口统一处理：普通节点、文本、注释 anchor、克隆节点、根节点、宿主接管的 root。保持 `retain/release`、脱离节点 sweep、焦点和事件回收语义。

这是减少 TS 表示开销，不改变 PocketJS 的原生绘制，也不要求应用采用 DOM。它比单纯压缩源码更直接作用于挂载时的存活对象数量，但目前**不能承诺节省多少 MiB**。

测量用相同节点类型、文本与样式建立不同规模的树，比较挂载增量、每节点平均增量、函数 / 对象数量、分配块数、峰值与卸载后的回落。随后在完整 App 上测量，确认合成场景的收益仍然成立。节点 TS 表示变小不会自动缩减 Rust 节点存储，两边分别统计。

### 5.3 应用侧减少细碎分配

先处理测量中靠前的分配来源：

- 大模型、历史数组和 typed array 保持普通对象，以轻量版本号驱动 UI；现有 `LogView` / `Terminal` 已采用这类做法，继续沿用。需要传递大对象时评估 `shallowRef`，不为“统一状态管理”新增深层响应式代理。
- `visibleRows()` 当前每次计算会创建数组和 `{ row, index }` 包装。可按内容版本与可见范围缓存，或维护小窗口；缓存必须有界，格式、字号、语言、颜色等影响结果的状态都参与失效。
- 静态选项、无状态处理函数和固定布局数据尽量共用；动态 style 的 key 保持完整，不能通过删除 key 优化而踩中当前“只增不删”的 diff 约束。
- 节点、watch、回调随未使用的子树真正卸载；已有清理机制先验证，不预设存在泄漏。循环打开弹层 / 切换视图后，存活数量应回落。
- 暂不引入大规模对象池。对象池可能把短命对象变成永久存活，只有高频分配且峰值收益明确时才采用固定容量复用。

## 6. 同一 UI 适配 480×272

当前 `PANEL_W = 272`，桌面默认视口 960×640，最小窗口 720×480。把它原样搬到 480×272，侧栏会挤占主要工作区；仅缩字号也没有解决节点数量和触摸面积。

建议提取共享布局函数，为同一 `App` 提供宽屏和窄屏两种布局：

- 宽屏继续保留左侧配置与右侧工作区。
- 窄屏将连接配置收进可打开的侧面浮层，复用现有字段组件与动作；默认主要显示收发区。高级接收 / 发送选项收进临时弹层，关闭后卸载内容。
- 收发区、设置框和状态栏根据同一个几何结果调整位置；发送区保留可用输入面积，通过收起配置与选项取得空间，而非复制一个板端发送组件。
- 折叠配置和模式切换不销毁连接或历史。仍是一页、一条连接、一个工作模式；浮层属于同页操作。
- 几何表同时服务绘制、弹层锚点、滚动总高、焦点与选区命中，不能只改视觉位置而保留桌面坐标常量。

布局分支按视口决定，后续也可在 macOS 小窗口中验证；产品功能开关按 profile 决定。两者独立，避免把窄屏行为写死成 AIC 专用组件。

沿用现有引擎约束：面板复杂堆叠使用 absolute + inset；弹层使用 Portal 与显式视口大小；可点击整块具有可命中的底色；组件空态不返回 `null`，条件分支放在父级子节点表达式中。

AIC 当前只有触摸输入、没有软键盘。共享 `TextField` 并不会自动产生可输入能力。首轮测试可用固定回环数据验证收发链；对用户开放发送前，需要接入输入适配，可用共享控件构建按需挂载的键盘。键盘打开时的节点峰值也要计入验收。

回环验证也需要改造装配：当前 `com === null` 时不会创建 `ComSession`。测试变体应显式注入仅用于回环的服务适配，让同一界面走通；真实设备操作返回不支持，不能把测试适配当作已完成的 UART / 网络桥。

## 7. 控制数据存活量和操作峰值

缩小源码和控件树后，仍需要有界数据链路。建议从以下实验配置开始，测量后调整，不作为已冻结的产品规格：

| 对象 | AIC 首轮实验上限 | 关键语义 |
|---|---|---|
| MessageBus | 256 帧 / 64 KiB payload | 正常历史逐出不伪报丢包；保留消息 id 和 source |
| LogView | 200 显示行 / 64 KiB 原始历史 | 替换桌面 `max(256 KiB, 行数×256)` 的容量计算路径 |
| Terminal | 首轮不创建；后续 0–128 行回滚 | 按视口初始化当前屏，计入 alt 屏和应答队列 |
| 发送编辑 / 单次发送输入 | 4 KiB UTF-8 | 超限拒绝并提示；不默默截断发往设备的数据 |
| 发送历史 | 10 条 / 总计 8 KiB | 同时约束字符串和配置副本 |
| 单次 RX 事件 / 合流积累 | 1–4 KiB / 8–16 KiB | 达限分段产出；具体帧语义先写入 SPEC |
| 宿主待投递队列 | 32–64 KiB，并限制事件数 | tick 边界限批量、FIFO、背压 / 溢出策略明确 |

消息总线和日志可以引用同一 `Message`，但各自保留窗口的并集决定对象何时能释放；不能默认两份 64 KiB 预算只占 64 KiB，也不能机械认定它们一定复制了两份 payload。

具体 TS 改造重点：

1. **合流先限额。** 在分块复制和拼接前检查预算，避免持续无静默输入无限积累。单个超大输入同样按块处理，不能等最终 emit 再截断。断开 flush、字节顺序和统计语义要有核心单测。
2. **格式化过程也限额。** HEX、转义和 ANSI 会放大数据；不要先创建整段巨大字符串 / 所有换行对象，最后才保留 200 行。采用有界分段处理，维持跨帧 UTF-8 / ANSI 状态与历史重排语义。
3. **颜色和缓冲所有权清楚。** `subarray` 会保活原 buffer；按测量选择紧凑复制或固定大小分块，不追求一律零拷贝。原始数据被总线持有时，不得复用底层内存修改其内容。
4. **字符宽度缓存有界。** 为嵌入式限制缓存条目或结合烘焙字符集合处理；显示替换符不改变原始 payload，HEX 仍无损。
5. **队列改造以证据驱动。** `core/message.ts` 目前用数组 `shift()` 逐出，可在高频场景评估真正的环形索引；改变 `peek()` / 增量遍历方式时避免每 tick 重新展开整个数组抵消收益。
6. **约束桥接前的突发。** Base64 / JSON 与解码结果可能同时存活，必须从宿主队列开始限批量。TCP 可背压，UART / UDP 需要明确丢弃计数；合并报告过载，避免每丢一包又制造一条系统消息。

这些能力用同一份核心代码实现，通过参数选择容量。桌面端保持原有默认值和语义；凡是共享算法变化，同步回归桌面边界场景。涉及接口和事件格式调整时，同步相关 bridge 契约、sim host 与测试。

## 8. 文案、字体与 vendor 修改范围

### 8.1 文案和字体使用同一裁剪清单

当前 `app/i18n.ts` 直接导入完整双语 JSON，AIC 打包又从全部语言包提取字形。后续由启用功能生成文案子集，JS 字典与烘焙字符使用同一清单。

第一步可以只按功能保守保留 key / 前缀集合，避免静态推导所有 `t()` 调用的复杂度。动态 key（如连接选项）、英文回退、占位符、系统错误及未知字符替换符都要覆盖；缺少 key 让构建失败。两份字典仍从现有 `assets/i18n/` 派生，不手工维护板端副本。

UI 继续使用 MiSans，mono 使用 JetBrains Mono。字体槽和字重是否裁减由实际使用决定；代码与包位于 XIP 不代表 atlas 或解码结构零 RAM。报告分别记录 flash 大小和挂载资源的内存增量。

### 8.2 vendor 中优先改什么

| 优先级 | 位置 | 修改目的 |
|---|---|---|
| 高 | `framework/src/native-tree.ts` | 节点方法 / 访问器共享、减少每节点 TS 分配 |
| 高 | `framework/compiler/jsx-plugin.ts`、`tools/build.ts` | Vue 转换前的功能特化、两阶段资源 / 模块图一致、缓存与报告 |
| 按接口需要 | manifest / plan 的契约、schema、resolver | 让新增构建输入可校验、可追溯；不混淆产品开关与宿主能力 |
| 测量后 | AIC guest allocator、`guest_realloc` | 减少 copy-realloc 峰值，保持对齐、失败保留原块和统计语义 |
| 后续备选 | 包契约与 QuickJS 加载器 | 离线字节码，主要降低编译开销；不会消除挂载后的对象 |

产品功能名、容量和 UI 取舍留在 PocketCOM，通用编译能力与适配器优化放进 PocketJS fork。luban-lite 首轮不重新划分堆或缩栈；后续有系统侧数据再讨论。vendor 改动分别维护子模块提交和父仓库 gitlink，记录工具链 / profile / 产物指纹供复测。

## 9. 实施顺序与验收

现有 S0–S5 分阶段诊断已经落地，运行期可用 `pjs_mem`，见 [AIC 接入记录](../host/rtthread/README.md)。后续补充业务与节点细分计数，不重新发明整套测量工具。

| 步骤 | 可独立评审的交付 | 验收依据 |
|---|---|---|
| 1. 固定对照与边界 | 补 SPEC 平台差异；保存现有精简 / 完整诊断数据；添加节点规模与共享组件增量场景 | 数据可区分编译、模型装配、UI 挂载和资源成本 |
| 2. 共享节点优化 | 独立修改 `native-tree.ts`，功能组合不变 | 同树分配量下降；Vue 适配和 macOS UI 回归通过 |
| 3. 功能裁剪与显式装配 | 构建特化、profile、终端 / MCP / 持久化模块边界；共享 App 可生成两种产物 | 禁用路径无代码 / 实例 / 资源残留；桌面功能保持 |
| 4. 共享窄屏布局与数据限额 | 复用原组件的折叠布局、受限模型、回环验证 | 480×272 可操作；无隐藏子树常驻；长流和格式切换有界 |
| 5. 设备 IO 与功能恢复 | 逐项接 UART / 网络、输入适配，按需开放终端 | 真机启动、持续流量、WiFi 与反复交互均满足预算 |

每步只改变可解释的因素。若完整诊断 App 仍不能在板端挂载，可先用同一套组件的增量构建测量；放宽内存的本机 probe 仅辅助分析。正式 `package:aic` 继续使用已验证入口，直到共享 UI 变体通过验收；当前精简页始终可作为诊断对照。

### 9.1 内存门槛

- 延用原方案中 `caps_peak ≤ 4 MiB` 作为首轮候选目标，随后由 WiFi / IO 实测校准。它不是硬件保证，也不等于 JS 配额。
- 同时看统一堆真实峰值、最大空闲块和失败记录。`sys` 包含系统与 guest，`caps` 和 QuickJS 指标与它存在包含关系，不能把三者相加。
- 从统一堆中扣除实测系统线程、WiFi / lwIP、应用峰值及分配器开销，仍需留出 IO 突发和碎片余量；各项峰值不一定同时发生，应记录组合场景。静态预算通过不能代表动态预算通过。
- 最大空闲块覆盖下一次最大实际请求及包装 / 对齐开销；128 KiB 仅可沿用为初始观察值，实际请求更大时提高门槛或拆分请求。
- 无分配失败、无持续增长的节点 / 订阅 / 存活容量；清屏或关闭弹层后回落到合理基线，不要求仍使用的模型和缓存全部归零。

### 9.2 回归矩阵

两种产品 profile 分别编译与校验，核心变更增加对应单测。已有脚本和命令沿用 `desktop-test` / `aic-build` skill；本文不引入尚不存在的可执行命令。

重点场景包括：

- 编译器：标记关闭 / 开启、嵌套条件、import 副作用、动态 key、未替换标记报错、冷 / 热缓存和目标切换。
- 共享节点：插入 / 移动 / 克隆 / 删除，文本与注释 anchor，Portal，焦点命中，事件清理；可从现有 `vendor/pocketjs/tests/vue-vapor-dom.test.ts` 等测试扩展。
- 桌面：全部连接类型、收发 / 终端切换不断连、终端后台 RX / 应答、设置草稿、MCP 门控、复制 / 粘贴、主题 / 语言 / 字号。
- AIC：至少 20 次冷启动、100 次功能区 / 弹层开关、30 分钟持续收发及超额突发；长行、碎片小包、HEX / ANSI、暂停恢复、格式切换、清屏和重连。
- WiFi：未开启、开启、连 AP、断开，以及有 / 无业务流量分别采样；输入界面和后续终端 alt 屏覆盖操作峰值。

每次记录主仓库 / vendor 版本、profile 指纹、包 / 固件 hash、JS / PAK 大小、节点与回调数量、`sys` / `caps` / QuickJS 指标、最大空闲块、失败请求、栈高水位、`turn_max` 和数据延迟。性能比较使用相同诊断配置，发布配置再复验一次。

## 10. 与 SPEC 和现有路线的衔接

本文确定共享 UI 的优化方向，具体功能取舍与上限仍为提案。实施时需先更新：

- SPEC §3.1：共享窄屏布局、配置浮层、命中与输入方式，保持单页 / 单连接。
- SPEC §3.2–3.4、§3.8：AIC 功能集合、容量、合流达限行为、超限输入提示及配置兼容；桌面既有语义明确保留。
- SPEC §4.4 与 M5 路线：从精简诊断页过渡到共享 App，保留“未经真机内存验证不切换正式入口”的要求。
- SPEC §5.4：功能文案裁剪和字体集合的一致性；若增加构建契约，同步 PocketJS 侧定义。

首轮最值得验证的是**共享节点表示变轻 + 无副作用的功能装配 + 在 Vue 转换前裁剪禁用功能**。它们直接作用于目前可定位的 TS 成本。若仍超预算，再按数据选择 realloc / 字节码和进一步的功能取舍；不预先承诺完整桌面功能能全部装入 8 MiB，也不把维护另一套 UI 作为默认退路。
