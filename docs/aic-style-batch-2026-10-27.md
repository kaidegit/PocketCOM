# Inline style 批量提交（2026-10-27）

> 后续同口径粗粒度真机A/B未显示净收益，批量版本组首开慢18%–21%，自动inline style合批已撤回。
> 当前源码恢复逐属性，保留可选C接口；结论和恢复固件见[粗粒度复测](aic-coarse-perf-2026-10-27.md)。

## 依据与边界

用户要求继续降低首次创建停顿，并尽量控制产品内存。最新真机TS日志见
[创建分段诊断](aic-ts-create-perf-2026-10-26.md)：配置首开254次native属性写入，
键盘414次；样式/原语属性处理占用明显。详细探针本身显著增加耗时，本文不据此宣称加速比例。

本轮只减少属性提交的JS/C边界，不改堆、配额、framebuffer、GE缓冲、产品feature或页面结构。

## 实现

- 共享ESP-IDF/AIC QuickJS绑定补齐已有可选HostOps `setPropBatch(ArrayBuffer)`。
  小端Float64三元组 `[nodeId,propId,value]` 同步按序调用既有core set_prop，因此沿用
  单次写入的动画取消、布局/绘制失效与节点代际检查。尾部不足24字节忽略；
  用memcpy读取，避免RV32不对齐double加载。ID/prop非有限或超出C整数范围时抛错，
  保留前面完整有效记录的写入；空包/无参数无写入，错误参数保留QuickJS TypeError。
- 共享native-tree inline style只收集有变化的属性，原有编码/未知key报错保留。
  单属性仍走scalar；多个属性编码成一个临时Float64包，经一次HostOp同步提交。
  编码后遇到错误会在finally提交之前有效属性，与scalar的错误前有效写入一致。
  无batch能力的宿主保留原逐属性路径；无变化不申请packet、不发写入。
- 临时number[]和Float64Array不挂到节点或长期缓存上。TS诊断继续保留以便真机比较
  `ui.setProp`与`ui.setPropBatch`次数，后续移除探针后才能验收净延迟。

该输入下系统峰值少10328 B，无新增常驻packet缓存；这不意味着所有负载都减少相同字节数。

这两组不启用TS诊断时钟，模拟的是产品路径；busy只让GC看不到空闲，不模拟实际UART/WiFi。

带临时TS诊断时钟的实际包native回放（三次）确认调用数：

| 首次操作 | 前包属性HostOp | 新包scalar + batch | 减少 |

| 键盘 | 413 | 0 + 54 = 54 | 86.9% |

离板输入与用户触摸存在细微差异，键盘413和真机414不强求一致。native耗时数毫秒且有抖动，
不作为AIC速度换算。基线/候选共用相同新版C绑定，前包仍走scalar，因此可比属性调用路径。

6个480×272 RGB565状态（初始、配置展开/收起、键盘展开/收起、发送区收起）前后零像素差异。
回放使用实际字体/QuickJS/core/CPU raster；不替代板上GE、DMA或观感验收。

回归包括：batch/scalar编码和顺序一致、无变化零提交、单项变化、未知key/编码错误前写入；
真实QuickJS C绑定测试空/缺失/错误类型、完整/尾部残缺包、NaN/范围错误、有效前缀提交。
其余共享真实Vue/core触摸、键盘、选区与布局回归按当前源码测试执行。
